# Herdr coordination evaluation

Inspect the existing installation before installing: binary via PATH, current-profile Hermes skill/plugins, Claude skill/hooks and their enabled settings. Installed files are not evidence that live agents loaded them. Load the canonical herdr skill and follow its environment guard. If HERDR_ENV is not 1, do not control or inspect the focused session; do not forge the variable to bypass that boundary.

Run a functional trial from a genuine Herdr-managed pane in an explicitly scoped test workspace/session. Preserve user focus and existing panes. Test fresh versus stale output markers, cwd, native session identity, blocked approvals, steering, transcript completeness, detach and restart separately. Preserve native exit and artifact evidence. Close only owned test resources.

Herdr done/idle and successful lifecycle waits are coordination hints, not task acceptance or proof of a specific prompt completing. Verify model/provider/effort through the native harness. Resource snapshots are not performance benchmarks.

Official references: https://herdr.dev/docs/install/ and https://herdr.dev/agent-guide.md. Use installed CLI help for exact version-supported syntax. Do not run a global installer or replace hooks merely to perform a comparison.
